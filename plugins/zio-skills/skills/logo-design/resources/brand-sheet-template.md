# Brand sheet template

One board per section, same width (e.g. 1480 px), stacked top to bottom. Name boards `Brand<N><Name>` (`Brand0Overview` … `Brand10Assets`). Keep exploration rounds on a separate page from the final sheet.

Each section: a mono label (`Brand sheet · 03 · Colour`), a title, a one-line intro, then numbered subsections (`3.1`, `3.2`, …). Show, don't describe: every rule gets a visual example.

## 0 · Overview

One-page summary; must stand alone.

- 0.1 The idea in three steps: how the mark is built, one picture per step.
- 0.2 The logo set: symbol (tile), symbol on dark, bare mark light/dark, one colour, favicon.
- 0.3 Colour: palette strip with hex values and one usage sentence.
- 0.4 Type: typefaces and their roles.
- 0.5 Voice: 3–4 traits and a working tagline (marked as a proposal).
- 0.6 In this sheet: section index; notes (outline text before shipping, trademarks).

## 1 · Logo

- 1.1 Symbol: the mark on its tile, large.
- 1.2 Construction: grid, proportions, radii, how the idea maps to the shape.
- 1.3 Logo with the full name: horizontal and stacked lockups, light and dark.
- 1.4 Clear space and minimum size: spacing unit, smallest sizes for symbol and lockup.
- 1.5 Misuse: stretched, recoloured, rotated, outlined, busy background, wrong font.

## 2 · Icon and favicon

- 2.1 App icon: rounded tile, maskable full-bleed version with safe zone.
- 2.2 Favicon: 16, 32, 48 px; simplified small cut if needed.
- 2.3 In a browser tab: light and dark tab mockups.
- 2.4 Profile avatar: square and circle crops (GitHub, Slack, X, Discord).
- 2.5 One-colour versions: ink, white, accent.

## 3 · Colour

- 3.1 Core palette: names, hex, role of each colour.
- 3.2 Tints and shades: a ramp for the accent (e.g. 50–900).
- 3.3 Light and dark mode: which value each role takes in each mode.
- 3.4 Contrast pairs: every text/background pair with its WCAG ratio and pass level.
- 3.5 Pairings: allowed and forbidden combinations.
- 3.6 Proportion: how much of a layout each colour should cover.
- 3.7 In the family: the accent beside sibling projects' accents.

## 4 · Typography

- 4.1 Typefaces: names, weights, licence, where to get them.
- 4.2 Typeface in the logo: weights, tracking, spacing in the lockup.
- 4.3 Type scale: sizes and line heights for display, headings, body, captions.
- 4.4 Code: monospace, sample block, syntax colours.
- 4.5 Rules: case, alignment, line length, what not to do.

## 5 · Voice and tone

- 5.1 Voice: 3–4 traits, each with a one-line meaning.
- 5.2 Tone by context: docs, errors, release notes, social.
- 5.3 Say this, not that: paired examples.
- 5.4 In practice: a sample README intro, error message, release note.
- 5.5 Taglines: 3–5 proposals, one marked as working.
- 5.6 Words: preferred terms, banned terms, product name spelling.
- 5.7 Naming third parties: how to refer to trademarks the project builds on.

## 6 · Visual and imagery style

- 6.1 Graphic language: shapes from the mark reused as a design element.
- 6.2 Pattern: a background pattern derived from the mark.
- 6.3 Diagrams: line weights, colours, node shapes, labels.
- 6.4 Code screenshots: frame, theme, font size.
- 6.5 Icons: stroke style, size grid, corner style.
- 6.6 Rules: no stock photos, gradients or clichés (list them).

## 7 · Hero banner

- 7.1 Website hero (e.g. 1352 × 440): logo, tagline, install snippet, call to action.
- 7.2 README banner (1200 × 300), light and dark.
- 7.3 Rules: what goes in, what stays out.

## 8 · Social cards

- 8.1 GitHub social preview (1280 × 640).
- 8.2 Open Graph / X / LinkedIn (1200 × 630).
- 8.3 Release announcement (1200 × 630): version and highlights as placeholders.
- 8.4 Talk title slide (1920 × 1080).
- 8.5 Rules: safe area, text size, light and dark.

## 9 · In the browser

- 9.1 Tab strip: normal and crowded, light and dark.
- 9.2 Other surfaces: bookmarks, search results, docs header, mobile home screen.
- 9.3 Markup and test checklist: `<head>` tags, manifest, `theme-color`, sizes to verify.

## 10 · Assets and tokens

- 10.1 Asset kit: every exported file with its name, size and use.
- 10.2 Tokens: colours, fonts, radii as CSS variables (`tokens.css`), light and dark.
- 10.3 Applications: sticker, docs header, merch or slides.
